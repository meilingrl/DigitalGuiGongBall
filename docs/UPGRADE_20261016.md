## 设计与取舍

本轮真实主线：注册/登录 → 三个模板之一 → 参数化三维工坊 → 保存 → 我的作品 → 刷新/退出重登/重启后打开并修改。

- 延续 Vue/Pinia/Three.js。Node + Express + SQLite 单服务，服务端会话使用 HttpOnly、SameSite Cookie，密码 scrypt，SQL 参数绑定；数据库文件不入 Git。
- 数据模型：users、sessions、works、schema_migrations；每个作品绑定 owner，修改携带 version 防止旧页面静默覆盖。
- shared/design.ts 定义共享作品配置与模板；Zod 运行时校验。API 返回可信错误，不回落 Mock。
- 三维为原创程序化镂空多层球（数字结构设计），模板影响纹样，参数控制层数/开孔/密度/材质/展开/剖视/聚焦层；保留原 GLB 和全部课程资料。
- 真实雕刻 CSG、加工级导出、联机、商城、预约、内容后台暂缓。旧模块作为课程演示入口并标明范围。
- 选择 SQLite 是为了免外部账号和本地可复现；当前是单进程演示系统，不宣称线上高并发。
- 相比另建 React/Next 或云数据库，这条路线迁移量小、演示零密钥；代价是需自行维护单服务 API 和会话。

## 协作契约

`DesignConfig`: schemaVersion:1; templateId:linglong|ruyi|lianhua; layers:整数2..6; patternScale:整数8..24; aperture:0.35..0.8; material:ivory|jade|bronze; separation:0..1; cutaway:boolean; autoRotate:boolean; activeLayer:整数0..layers（0=全部）。

模板：`{id,name,subtitle,description,config}`。用户：`{id,username,displayName}`。作品：`{id,title,description,config,version,createdAt,updatedAt}`。

- GET `/api/health`、`/api/templates`（公开）
- POST `/api/auth/register` `{username,displayName,password}`、POST `/api/auth/login` `{username,password}` → `{user}` + Cookie
- GET `/api/auth/me` → `{user}`；POST `/api/auth/logout` → 204
- GET `/api/works?search=` → `{works}`；POST `/api/works` `{title,description,config}` → 201 `{work}`
- GET `/api/works/:id` → `{work}`；PUT `/api/works/:id` `{title,description,config,version}` → `{work}`，旧版本 409
- 错误：`{error:{code,message}}`；未登录 401、非法输入 400、非本人/不存在 404。

### 续阶段设计与边界

- 幂等键为 UUID，可选以兼容旧 API 客户端；新 UI 对作品写入始终携带。数据库以 `(owner_id,key)` 唯一记录方法、资源、规范化载荷摘要和原结果，业务变化与记录在同一事务提交。相同键/不同操作或载荷 409 `IDEMPOTENCY_CONFLICT`，相同操作重放原结果，不重复创建或递增版本。记录暂不自动过期。
- `Work` 增加 `deletedAt: string|null`；旧数据迁移为 null。回收站不做永久清空。普通 GET/PUT 排除回收站内容，移入/恢复均带 version 并递增；复制只接受本人有效作品并创建独立版本1。
