# 如何理解和介绍这次升级

原项目是一套课程高保真前端原型：内容、模板和多个业务模块已经可演示，但登录为跳转，投稿只在组件内存中，雕刻工具未驱动几何，三维模板共用 GLB。本轮将价值集中到一条可验证的创作闭环，保留原文件和课程范围记录。

## 七个值得面试讨论的问题

**为什么继续 Vue，选择 SQLite？** 保留现有内容和技术积累，把时间用于业务闭环。SQLite 无需云账号和独立数据库服务，事务和文件持久化足以支撑本地单进程演示。它不是多实例服务的扩展设计：未来需评估异步数据库访问、备份保留/加密和迁移运维，再决定是否切换数据库。

**登录页为什么不能代表权限实现？** 路由守卫只改善体验；真正权限在每次服务端作品查询和更新中用 `owner_id` 过滤。不能相信客户端提交的用户 ID。会话随机令牌放在 HttpOnly Cookie，数据库只保留摘要；退出删除服务端会话。相关代码在 `server/auth.ts`、`server/app.ts`，相关真实 HTTP 失败场景在 `server/tests/api.test.ts`。

**两个页面编辑同一件作品会怎样？** 每次更新带版本号，SQL 原子执行 `WHERE id=? AND owner_id=? AND version=?`，成功后版本递增。旧页面得到 409，前端保留草稿并提供读新版本入口；这是乐观并发控制，不是自动合并。请求晚于页面退出或显式重新读取完成时，也必须用编辑周期标识忽略过期响应，避免错误跳转或覆盖新页面状态。

**版本号和幂等键为什么缺一不可？** 版本号保护两个不同编辑意图不互相覆盖；请求键用来确认同一次操作。保存实际提交后响应丢失，直接带旧版本重试会409，而重新POST会重复创建。现在业务变化与 `(owner_id,key)` 的原响应记录同事务提交，相同请求可在重启后重放。前端持久保存不可变key/载荷，同时把后续编辑留作下一次意图。401仅代表本次确认被认证拦截，不能据此清掉此前未知提交。另一标签登录其他账号也不能让旧意图随Cookie漂移：请求携带预期账号，服务端只做一致性比较，真正归属仍取会话与ownerSQL。`tests/reliable-save.integration.test.ts` 用真实HTTP提交后丢弃响应，再重启、重登和恢复验证，而非永远成功的Mock。

**为什么备份SQLite不能直接复制主文件？** WAL模式下已提交数据可能仍在辅助日志中。维护命令通过SQLite一致性快照生成新文件，再校验完整性、外键和已知结构；恢复从不覆盖当前文件，并撤销旧会话。独立审查还发现SQL删空白导致结构签名碰撞、发布时外来WAL改变恢复结果，已用失败回归推动token/实际结构检查与发布前后文件身份检查。其边界是可信本地目录，不是生产灾备或恶意操作系统竞态防护。

**镂空究竟是不透明模型还是贴图？** `src/three/ornament.ts` 构造有厚度的球面纹样框与连接结构。射线测试确认开孔中心可穿过，边框实际挡住射线；密度、模板和开孔尺度改变顶点。各层拥有独立几何与材质，展开与剖视帮助理解层次。限制是风格化数学生成，不是文物扫描复原；裁切截面也没有实体封盖。

**构建通过后，为什么还需要浏览器和进程测试？** 类型检查不会发现 GPU 不可用、材质过曝或移动布局遮挡。数据库重开测试也不同于真实进程退出。`scripts/verify-restart.mjs` 从空库启动编译后服务，通过 HTTP 写入、正常重启、更新、强制终止和重登再读；它验证已提交数据在进程终止后的恢复，不证明断电、磁盘损坏或生产灾备。截图和浏览器路线补充了另一层证据。

## 可用的简历表述（选择 2–3 条，理解后再使用）

1. 将非遗 Web 3D 课程原型升级为 Vue 3 + Express + SQLite 全栈创作工坊，实现注册登录、三维配置编辑、作品保存检索及重新打开；通过独立数据库 HTTP 测试验证用户隔离与跨进程持久化。
2. 基于 Three.js 实现三种参数化多层镂空球体及展开、剖视、图层聚焦和材质切换，使用射线与几何测试验证真实开孔、独立层级和资源释放，并完成桌面与移动视口演示检查。
3. 实现作品版本控制与事务内幂等请求记录，配合按账号隔离的设备草稿及未确认请求恢复；通过真实HTTP响应丢失、跨登录和跨进程重放测试验证同请求不重复写，并将业务/几何/备份恢复检查接入 GitHub Actions。

证据入口：`server/tests/`、`tests/`、`scripts/verify-restart.mjs`、`.github/workflows/ci.yml`。测试数量以当前运行结果为准，不把数量当作质量结论。浏览器检查是代理执行的有限验收，不是用户人工验收。

## 暂时不能声称

不能声称上线运营、真实用户量、高并发、性能提升百分比、云端可靠性、生产安全认证、多人实时雕刻、真实雕刻/加工导出、准确历史纹样复原，或旧商城/社交/预约已全栈化。最高几何预算仅是静态三角形数量，不能推导帧率。

本轮大量代码由代理实现和独立审查；应能讲清实现、验证和边界，不能把未经本人理解的代码说成全部手写。建议先从 `shared/design.ts → server/app.ts / works.ts / idempotency.ts → src/composables/useAtelierDocument.ts → src/views/AtelierView.vue → src/three/ornament.ts` 读主线，再亲自按 README 运行并改一个参数字段、添加一个失败场景测试。

## 恢复、回滚与下一步

升级分支：`upgrade/fullstack-atelier-20261016`。起点 `acbe033520e981446fc5ceda217634a358f741f6`，未合并 main。先确认 `git status` 干净，停止本地服务，妥善保留 `data/` 与 `.env`：

```bash
# 返回原课程默认分支（本轮未修改该分支）
git switch main
npm ci
npm run dev

# 或仅查看确定的原始提交
git switch --detach acbe033520e981446fc5ceda217634a358f741f6

# 回到升级成果
git switch upgrade/fullstack-atelier-20261016
npm ci
npm run build:all
npm start
```

不要使用 `reset --hard` 或 force push。若只想撤销某个已推送提交，在升级分支用 `git revert <SHA>` 创建恢复提交，先检查依赖关系、测试和数据库兼容性再推送。当前迁移为v2，无破坏性自动降级。代码回滚不会删除数据库或回退数据；回滚到续阶段之前的代码时，先备份现库，使用升级前v1快照的离线副本；本工具restore会迁移到当前v2，不是数据库降级工具。不要用旧API解释v2回收站状态。按依赖的逆序撤销，不能单独撤销数据库/API却保留依赖它的维护工具和页面。

续阶段已补齐幂等键、草稿、分页/回收站及本地备份恢复。后续优先：亲自验收与阅读代码 → 真实手机性能与WebGL故障注入 → 设备恢复记录的多标签协调、请求记录保留/限额 → 如需公开部署再做HTTPS、监控、找回账号、加密/异地备份与部署审查。不要先扩展独立业务模块。
